# ADR-0018: 全局中转站与每 Agent 绑定

## 背景

旧版按 Codex、Claude、Grok 各维护一份中转站列表。同一个地址和密钥要填三次，模型和推理档位也各存一份。上一轮增量改造把供应商和 Agent 目录加在旧列表旁边，运行时同时保留两套模型，迁移和同步都要兼容两边，复杂度持续上升。

## 决策

第二代桌面端直接采用新模型：

- `suppliers` 是全局中转站列表，保存名称、地址、密钥、备注、协议集合和模型目录。
- 每个 Agent（Codex、Claude Code、Grok CLI、OpenCode）有一份 `bindings` 目录。
- 每条绑定引用一个 `supplier_id`，并保存该 Agent 自己的模型、协议、推理档位、上下文长度、压缩比例，以及 Agent 专属字段。
- 每个 Agent 的每个来源（App / WSL）同时只启用一条绑定；启用时把供应商凭据和绑定参数写进目标配置文件。
- 旧的三份中转站列表只作为一次性导入来源，不进入新版运行时。

## 后果

- 同一组凭据只保存一次，切换 Agent 不需要重填。
- 一个 Agent 可以保存多条来自不同中转站的绑定，按需切换。
- 删除被绑定引用的中转站会被拒绝；删除正在启用的绑定会被拒绝。
- 同步载荷按供应商 id 和绑定 id 合并，不再按工具分三份。

## 状态

已采纳。实现见 `cxc-v2/cxc-v2-core/src/supplier.rs` 与 `agent.rs`。
