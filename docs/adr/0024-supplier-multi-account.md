# ADR-0024: 中转站多账号

## 背景

一个中转站只能保存一个 API Key。同一端点有多个账号（个人/团队、不同额度、不同模型权限）时，只能把它建成多条中转站记录：地址、协议、模型目录全部重复，模型测试结果也各存一份；换账号要重新选一遍模型。

## 决策

把「中转站」和「账号」拆成两层。

- **中转站**：一个端点。保存 Base URL、协议集合、模型目录、备注。
- **账号**（`SupplierKey`）：端点下的一个 Key。保存名称、Key、备注。一个中转站至少一个账号，可以有多个。
- **绑定**：引用「中转站 + 账号 + 模型 + 参数」。`key_id` 为空表示跟随中转站默认账号。

账号解析顺序：`binding.key_id`（存在且有效）→ `supplier.default_key_id`（有效）→ `supplier.keys[0]`。

配置版本升到 5，同步载荷同步升到 5。

## 各操作使用的账号

| 操作 | 账号 |
|---|---|
| 探测协议 | 默认账号 |
| 拉取模型 | 默认账号 |
| 单模型 / 批量测试 | 详情对话框里选中的账号 |
| 绑定对话框的「测试」 | 该绑定解析后的账号 |
| 写入目标文件 | 该绑定解析后的账号 |

模型测试结果记录 `tested_key_id`，界面在状态列下方显示账号名。

## 删除与校验

- 删除被绑定显式引用的账号：拒绝，提示账号名与引用它的 Agent。
- 删除默认账号：允许，默认回退到剩余账号中的第一个。
- 删除最后一个账号：拒绝。
- 绑定保存时 `key_id` 指向不存在的账号：拒绝。

## 迁移

- 版本 4 → 5：`supplier.api_key` 变成 `keys: [{ name: "默认", api_key }]`，`default_key_id` 指向它；绑定的 `key_id` 为空（跟随默认）；模型测试结果补 `tested_key_id: None`。
- 版本 3 / 2 / 1：先走现有迁移链，再套用 4 → 5 规则。
- 旧配置文件只读。

## 后果

- 同一端点的多个账号共享协议集合与模型目录，不再重复配置。
- 切换默认账号后，跟随默认的绑定下次写入即使用新 Key，不必逐条改。
- 需要固定账号的绑定显式选择账号，绑定行摘要会多显示一段账号名。
- 账号级模型差异靠测试结果判断，模型目录仍按端点共享。
