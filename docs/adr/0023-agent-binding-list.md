# ADR-0023: Agent 绑定列表

## 背景

ADR-0022 把每个 Agent 收敛成「一份配置」，Agent 页只有一张卡片，卡片里同时放展示和全部表单字段。实际使用中：

- 表单字段多（协议、中转站、模型、推理档位、计划模式档位、上下文、压缩比例、Claude 映射、web_search），卡片高度超过一屏，列表感消失。
- 没有「切换」的概念：改配置就是覆盖，想保留两套参数只能自己记下来。

## 决策

1. 每个 `(工具, 环境)` 保存多条绑定，同一时刻只有一条「使用中」。
2. Agent 页 = 工具切换 + 环境切换 + 绑定列表 + 「新建绑定」。不再有独立的「当前启用」区块；使用中的那条在列表里高亮（左侧蓝色竖条 + 浅蓝底 + 「使用中」徽章）。
3. 列表每行只放摘要：模型名（主）、`中转站 · 协议`（弱）、参数 chips、最近一次测试结果。表单移入 `BindingDialog`。
4. 「启用」= 写入目标文件成功后切换 active；编辑使用中的绑定保存后自动重写；编辑其他绑定只入库。
5. 使用中的绑定不能直接删除，要先启用别的。
6. 绑定重新带上稳定 `id`，配置版本升到 4；同步载荷升到版本 4。
7. 托盘只列每个 Agent 使用中的那条，点击重新写入。

## 迁移

- 版本 3 → 4：单份配置变成一条绑定并设为使用中。
- 版本 2 → 4：全局来源对应的环境保留全部绑定（`active_wsl` / `active_app` 决定 active，缺省取第一条），另一环境只保留它的激活项。
- 版本 1（旧版应用）：每个旧 provider 生成一条绑定并设为使用中。
- 旧配置文件只读。

## 后果

- 一屏能看到多条绑定和各自参数，切换成本降到一次点击。
- 表单与列表分离，卡片高度不再随字段数量增长。
- 配置文件与同步载荷都多一层 `bindings` 数组，读取旧版本时需要收敛。

## 状态

已采纳。实现见 `cxc-v2/cxc-v2-core/src/agent.rs`、`config.rs`，界面见 `cxc-v2/cxc-v2-desktop/src/components/agents/`。
