# ADR-0022: 环境并入 Agent 身份，每个 Agent 一份配置

## 背景

ADR-0018 的模型是「全局中转站 + 每个 Agent 一份绑定目录 + 每个来源一条启用绑定」，来源（App / WSL）是全局开关。实际使用中暴露两个问题：

- `Grok (WSL)` 与 `Grok (Windows)` 是两个不同的安装、两套配置文件，用户把它们当作两个 Agent；全局来源开关与这个心智不符。
- Agent 页同时展示「当前启用」和「绑定目录」，同一条配置出现两次；多份绑定在大多数场景下用不到。

## 决策

1. 环境成为 Agent 身份的一部分。`Agent = (工具, 环境)`，环境取值为 `wsl` / `windows`。删除全局 `source` 字段与顶栏的来源切换。
2. 每个 Agent 只保留一份配置，删除 `bindings` 列表与 `active_app` / `active_wsl`。
3. Agent 卡片内直接编辑，点「保存并写入」立即写目标配置文件；写入失败时 CXC 配置保持不变。
4. 只显示当前机器能访问到的环境：Linux / WSL 下 WSL 本机可达，Windows 通过 `/mnt/c` 判断；Windows 下相反，通过 `wsl.exe` 判断；macOS 只显示本机侧。
5. 自定义目录按 `(工具, 环境)` 各一个。
6. 配置文件版本升到 3。版本 2 的 `bindings` + 激活项收敛为每个环境一份配置：`active_wsl` 落到 `wsl`，`active_app` 落到 `windows`，WSL 侧没有激活项时退回第一条绑定。
7. 同步载荷升到版本 3，`agents` 直接携带每个工具的两个环境配置；读取版本 2 / 1 载荷时先收敛再合并。
8. 托盘菜单改为「按 Agent 重新写入」，因为不再有可切换的多份配置。

## 后果

- `Grok (WSL)` 与 `Grok (Windows)` 各自独立配置、独立写入，互不影响。
- Agent 页只有一张卡片，模型名作为主标题，中转站名与协议作为弱化副标题。
- 换中转站/模型就是改这份配置，不再有「启用」这一步。
- 旧版应用与 v2 配置都能迁移；旧配置文件只读。

## 状态

已采纳。实现见 `cxc-v2/cxc-v2-core/src/agent.rs`、`config.rs`、`detect.rs`。
